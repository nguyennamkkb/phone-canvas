phone-canvas

Design board mô tả dự án — nguồn: README.md, package.json, 7 file src/, herdr-context (đọc ngày 2026-10-02)

1. Dự án là gì

phone-canvas là một design board chứa các phone screen dưới dạng hình chữ nhật render HTML thật bên trong <iframe srcdoc>, rồi đọc số đo chính xác của từng element để lập trình viên viết SwiftUI từ đó. Không giả lập thiết bị, không viewport cố định, không vùng scroll bị che: một screen cần 992pt sẽ là hình chữ nhật cao đúng 992pt.

Nguyên tắc xuyên suốt: <iframe> là nguồn sự thật của layout, SPEC là hợp đồng handoff, còn panel chỉ là khung nhìn lên spec đó.

2. Kiến trúc & luồng dữ liệu

Screens HTMLproject/*/screens/*.html→ Registryderive.ts pure→ Board / PhoneNodecompose + srcdoc iframe→ bridge.jsRAW postMessage→ infer.tsbuildSpec()→ SpecPanelbảng spec + Copy JSON
  1. Screens HTML → registry (derive). Folder chính là registry: mỗi thư mục project/<id>/ gồm screens/*.html (id = tên file, duy nhất toàn cục), components/*.html (phạm vi từng project), tokens.css, assets/, project.json. Toàn bộ luật khám phá nằm trong một hàm pure duy nhất deriveRegistry() (src/projects/derive.ts); trình duyệt đọc qua import.meta.glob (registry.ts), Node đọc từ đĩa (scripts/scan-projects.ts) — không bên nào tự đặt luật.
  2. Board / PhoneNode (iframe srcdoc). Mỗi screen là một node React Flow (src/canvas/Board.tsx, PhoneNode.tsx): hình chữ nhật rộng bằng device, chứa <iframe srcdoc> chạy HTML thật. Tài liệu hợp nhất duy nhất là composeScreenDoc() (src/extractor/compose.ts) — app, export và locate cùng dùng nên không thể lệch nhau.
  3. bridge.js gửi RAW xuống. Script chạy bên trong iframe (src/extractor/bridge.js) đo getBoundingClientRect() và computed styles rồi postMessage nguyên bản lên parent. Định danh message dùng token/opaque thay vì so sánh WindowProxy (iframe sandbox không giữ identity ổn định).
  4. infer.ts — nơi duy nhất biết SwiftUI. buildSpec() (src/spec/infer.ts) diễn giải phía parent: nhận diện role (VStack/HStack/ZStack/Text/Image/Button/Spacer/Circle/Capsule/Rectangle, còn lại là Block (out of subset)), đổi màu sang hex, tính lineSpacing = lineHeight − size, đặt tên weight… mà không chạm tới iframe.
  5. SpecPanel. src/inspect/ (InspectorContext.tsx định tuyến message, SpecPanel.tsx cây element + bảng spec): chọn screen + độ rộng device, duyệt cây, click dòng hoặc click trực tiếp element ở chế độ Đo đạc, đọc spec, Copy JSON đưa cả screen hoặc một element cho LLM.

5 invariants (rút gọn từ README)

1. 1 CSS px = 1 pt. Iframe luôn render đúng kích thước tự nhiên của device, chỉ camera canvas scale bằng transform; cấm CSS zoom/scale lồng nhau.
2. Khung cố định, body cuộn. .device cao đúng device; chỉ một scroller dọc (.body, hoặc .body-fixed cho trang vừa khung — tràn là lỗi audit báo, không phải scrollbar ẩn).
3. Safe area là region khai báo rõ ràng, không phải inset. Status bar + home indicator là element thật do shell (compose.ts) sở hữu, ánh xạ sang .safeAreaInset, loại khỏi capture.
4. Raw xuống, diễn giải lên. Bridge gửi computed styles nguyên bản; mọi diễn giải SwiftUI nằm ở infer.ts phía parent (type-check được, sửa không chạm iframe).
5. Screen fluid mọi chiều rộng. Viết bằng token class (col, row, paper-card, var(--s*)), không px cứng theo một device; khác form-factor căn bản (ví dụ iPad list+detail) thì tách screen riêng, cấm nhánh if-device trong một file.

3. Chức năng core

  • Board (design board). Iframe inert ở chế độ Di chuyển (kéo node, pan, zoom; click node để chĩa panel vào). Khung đơn giản / khung máy chỉ trang trí, không đổi bất kỳ số đo nào. + Màn hình nhân bản screen lên board; Vừa khung fit board vào viewport. App là vỏ Dashboard ↔ Board theo hash route (src/App.tsx), project tùy biến lưu localStorage, Cmd/Ctrl+. ẩn/hiện panel.
  • Đo đạc + Spec panel + Copy JSON. Chế độ Đo đạc bật pointer events cho iframe: hover highlight, click chọn. Panel đọc spec từng element (box, layout, padding, typography, surface, image) và Copy JSON toàn screen hoặc element đang chọn cho LLM.
  • Export PNG qua Chrome CDP. npm run export: mọi screen → exports/*.png. Mặc định là khung device (device mẫu 390×844 @2x); --full chụp cả trang (hậu tố -full để không ghi đè). Không phụ thuộc cài thêm: script lái Chrome có sẵn trên máy qua DevTools protocol. Export loại bỏ chassis trang trí, cầu đo và data-pc-* để ảnh handoff trung thực.
  • Locate theo tọa độ. npm run locate -- --screen my-screen --x 195 --y 640 (điểm tính bằng pt từ góc trái-trên device — cùng hệ tọa độ panel báo): xuất ảnh vùng element (+padding) và JSON spec kèm ancestors. Điểm rơi vào status bar/vùng trống báo miss nhưng vẫn chụp ô vuông quanh điểm.
  • Tokens / components / regions: lint + audit gates. npm run lint = typecheck + lint tokens/subset/components/regions; npm run audit:regions đo layout thật trong Chrome (rect 44pt, một scroller, tràn, band shell, fold 50/50, seam nền); npm run gate = lint + audit + test. Shell sở hữu mọi band (status/nav/tab/home): screen chỉ khai báo nội dung qua data-slot="back|title|right", data-tab và dải .body/.body-fixed. Chuẩn phone: nav ≥ 44pt, tab bar 68pt với 3–5 đích (icon + nhãn), gutter 16pt lưới 4/8, mọi element tương tác ≥ 44×44pt.
  • Quản lý project/screens. npm run project -- add my-app, npm run screen -- add --project my-app --name my-screen (id = stem tên file, metadata dòng đầu <!-- pc {"title":"…"} -->), npm run rename-screen, npm run delete-screen. Registry hiện có: calo-ai, foundation-kit, frank-sound, scratch-tablet, scratch-watch, scratch-widget.
