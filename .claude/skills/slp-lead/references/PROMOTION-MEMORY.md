# PROMOTION & MEMORY — Turn evidence into lessons + expertise

> Use at STEP 5/5b. Keep 2 pipelines apart: lessons (what the project knows) vs
> expertise (what the peer proved). Never merge them.

## 1. Two independent pipelines

```text
Task evidence
  ├── Reusable lesson ──→ knowledge proposal ──→ project/global knowledge
  └── Demonstrated capability ──→ expertise proposal ──→ peer confidence
```

- *"I learned X" ≠ "I am good at X".*

## 2. Proposal Rubric (PROPOSED → ACCEPTED / REJECTED / DEFERRED)

| Check | ACCEPT when |
| :--- | :--- |
| Applied/Impact | Concrete (chose Y instead of Z), not just a list of files read |
| Verification | Real command + exit code |
| Lesson | Has context + mechanism; seen once → provisional |
| Difficulty | Worthy (never promote ESTABLISHED on a trivial task) |

- ACCEPTED ≠ ESTABLISHED: `provisional → calibrated (≥1 pass) →
  established (≥3 pass + difficulty + consistent behavior)`.
- Vague evidence → REJECTED (fail closed, never guess).
- Promising but thin → DEFERRED (record conditions for later accept).

## 3. Demotion / Restriction

- Repeated verified failure in a sub-area → add a **restriction**
  (e.g. `ESTABLISHED + restriction: complex async state`), don't wipe everything.
- Serious boundary violation / untrustworthy profile → demote per roster.
- Record evidence for both promotion and restriction.

## 4. MEMORY Distillation Bar (anti MEMORY POLLUTION)

A lesson reaches global MEMORY.md only when all 4 hold:

1. **Reusable** — outlives the current task.
2. **Stable** — mechanism verified, not a one-off guess.
3. **Project-wide** — other teammates need it too, not one peer's episode.
4. **Verified** — answer-path + verdict as evidence.

Otherwise → stays in peer-local `_state/MEMORY.md`.
